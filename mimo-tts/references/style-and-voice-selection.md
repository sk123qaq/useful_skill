# 音色与风格的选择（MiMo TTS）

## 别猜，直接出样对比

TTS 限时免费，一段千字文本单次合成只要 40–50 秒 —— 所以「哪种音色/风格更合适」不要用文字讨论，**一次批量跑 2–3 个候选，把成品一起交给用户挑**。常用组合示例（同一段文本、同一风格指令）：

```bash
S=~/.agents/skills/mimo-tts/scripts/tts.py
T=<测试文本或 -f 文件>
python3 $S $T --voice 冰糖 -o a_冰糖.mp3 --style "自然口语，句间有呼吸感"
python3 $S $T --voice 苏打 -o b_苏打.mp3 --style "语速稍快，播客对谈的松弛感"
python3 $S $T --model mimo-v2.5-tts-voicedesign -o c_设计男声.mp3 --style "低沉的四十岁男声，语速舒缓，深夜电台"
```

交付时**发 mp3，不发 wav**：wav 是 24 kHz/单声道未压缩的（≈48 KB/秒，3.5 分钟就 10 MB），聊天里又大又难试听；mp3 接口原生支持，体积约为 wav 的 1/6。

## 控制风格的两个通道

| 通道 | 放哪 | 状态 |
|---|---|---|
| 自然语言风格指令 | `role: user` 的 content | 本机已验证可用（如「低沉的四十岁男声，语速舒缓，像深夜电台主播」） |
| 内联音频标签 | `role: assistant` 的目标文本里 | 官方文档记载，本机未逐项验证 |

内联标签按文档：在目标文本**开头**加 `(风格)`（多种风格写在同一对括号内，分隔符不限）可指定发音风格；`(唱歌)歌词` 走唱歌模式（仅 `mimo-v2.5-tts`）。**用前先拿一句短文本探一下**：确认标签被识别而不是被念出来，再套到长文上。

## 风格指令起始模板

先把想要的**说话人身份 + 语速 + 情绪 + 场景参照**四件事写齐，比一个形容词有效得多。可直接改用的骨架：

- 播客对谈：「松弛的对话语气，语速中等，句尾稍降，像在跟一位懂行的听众聊天」
- 新闻播报：「中性专业，语速稳定偏快，重音落在数字与专有名词上」
- 有声书旁白：「低音量叙述感，语速舒缓，长句在逗号处稍作停顿」
- 教学讲解：「清晰、耐心，关键定义前后各留一个短停顿」
- 情绪台词：「压抑的愤怒，前半句收紧、后半句放缓」

每条都当草稿用：出来后听一遍，把不对的那一项（太快/太平/太吵）改掉再跑，不要一次改多项 —— 一次只调一个维度才能知道是谁起作用。

## 语速与后期微调

官方参数里**没有数字语速项**（`audio` 只有 `format` / `voice` / `optimize_text_preview`），语速只能靠风格指令描述。需要精确倍数时用 ffmpeg 事后调：

```bash
ffmpeg -y -i in.mp3 -filter:a "atempo=1.15" out.mp3     # 1.15 倍速，音高不变
```

`atempo` 单次有效范围 0.5–2.0；超出就串联两次（如 2.4 倍＝`atempo=1.6,atempo=1.5`）。

## 长文分工

超过约 1200 字的文本让脚本按句切块拼接；**每块用同一个音色 + 同一条风格指令**，否则块与块之间会听出腔调跳变。拼接后的成品一定核一下「时长 ≈ 逐块合计」（脚本会告警），块丢了通常就丢在拼接这一步。
