# 业务指标

## 当前定位

这份文档保留的是长期稳定成立的业务指标口径。

它不是脚本说明，也不代表 `data_analysis_pro` 已经内建了漏斗、留存、同期群、LTV 的专用 runner。

## 使用前先确认三件事

- 分析单元是什么：用户、订单、会话、天，还是账户
- 去重口径是什么：同一用户同一步骤是否只算一次
- 时间口径是什么：自然日、注册后第 N 天、账期月，还是交易日

如果这三件事没说清，公式本身很容易算对、口径却错。

## 1. 漏斗

适用前提：

- 你有明确的步骤顺序
- 能识别同一个实体在不同步骤中的推进过程

常见公式：

- 步骤人数 = 到达该步骤的用户数
- 步骤转化率 = 当前步骤人数 / 上一步骤人数
- 总转化率 = 当前步骤人数 / 第一步人数

至少要检查：

- 是否按正确实体去重
- 是否存在步骤回退或重复触发
- 是否把不同渠道、不同流量质量混在一起算

建议额外报告：

- 流失最严重的环节
- 该环节的绝对流失人数

## 2. 变现

常见公式：

- 付费率 = 付费用户数 / 活跃用户数
- ARPU = 总收入 / 活跃用户数
- ARPPU = 总收入 / 付费用户数
- 复购率 = 重复购买人数 / 购买总人数

至少要检查：

- 收入口径是否含退款、税费、补贴
- 活跃口径和付费口径是否在同一时间窗
- 收入是否被极少数用户主导

如果分布极偏：

- 除了均值，还建议补中位数、分位数或鲸鱼用户占比

## 3. 留存

适用前提：

- 能识别用户首次获取时间
- 能识别后续回访/活跃时间

常见公式：

- 第 N 日留存率 = 第 N 日活跃用户数 / 第 0 日获取的新用户数

至少要检查：

- 留存定义的是“登录”“活跃”“下单”还是别的行为
- 是否按获取日期对齐，而不是只按自然日对齐
- 样本是否因为埋点或数据缺口被截断

## 4. 同期群

常见口径：

- 同期群留存矩阵 = 第 k 期留存用户数 / 同期群初始规模

至少要检查：

- 同期群是按天、周还是月
- 不同 cohort 的观察窗口是否足够可比
- 渠道结构、活动投放、产品版本是否改变了 cohort 组成

如果渠道 mix 差异很大，不要直接把 cohort 差异写成产品效果差异。

## 5. 生命周期价值（LTV）

常见公式：

- LTV = 该同期群的总收入 / 该同期群的用户数

至少要检查：

- 比较的 cohort 是否处于相同生命周期长度
- 是否把一次性促销收入当成长期价值
- 付费率变化和客单价变化是否被拆开分析

更稳妥的写法通常是：

- 固定到“注册后第 30 天 LTV”
- 或固定到“获取后第 12 周累计收入”

## 6. 财务指标

常见公式：

- 收益率 = (期末价值 - 期初价值 + 现金流) / 期初价值
- 波动率 = 收益率的标准差
- 夏普比率 = (平均收益率 - 无风险利率) / 波动率
- 最大回撤 = 峰值到谷值的最大跌幅

至少要检查：

- 收益率序列频率是否一致
- 无风险利率是否与收益率频率匹配
- 现金流是否按正确时点处理

## 防护准则

- 先统一口径，再计算指标。
- 不要把不同时间窗、不同分母、不同实体粒度的指标直接横比。
- 如果某个指标非常依赖定义选择，就把定义写进结论正文。
- 如果用户最关心的是决策，不要只给公式，要补“变化来自哪里”的拆解。
