# 中文 DOCX / PDF 分析报表交付规范

## 目的

这份文档定义 `data_analysis_pro` 在编写正式中文报表时的内容规范。它面向两种交付物：

- 中文 `.docx` 分析报表
- 中文 `.pdf` 分析报表

设计目标：

- 让非技术读者可以读懂
- 保留足够多的技术依据，便于复核
- 对专业名词给出简短解释
- 对关键指标明确写出“当前数值说明什么、它重要在哪里、背后意味着什么”

## 何时使用

当用户明确要求以下任一交付物时，使用这套规范：

- 正式汇报版分析报告
- Word 版分析报告
- PDF 版分析报告
- 可发给管理层、客户、合作方的分析报告

## 当前定位

本文件是写作规范，不是导出流程说明。

当前 `data_analysis_pro` 没有稳定的正式报表导出管线。

如果用户要正式文档，当前更现实的做法是：

1. 先基于实际运行产物写出结构化 Markdown 报告
2. 再把这份结构和下面的规范交给 `docx` 或 `pdf` 相关能力做成正式文档

## 报表必须满足的内容要求

正式 DOCX / PDF 报告的内容，应围绕这次实际分析过程来组织，核心应回答下面这些问题：

- 要分析的问题是什么
  - 如果本次分析过程中实际看了多个点，应整合后一起写清楚，而不是拆成互不相干的小报告。
- 用了什么方式读取数据
- 如何查看当前数据情况
- 如何查看异常值、缺失值和其他数据质量问题
- `describe.py` / `feature_risk.py` 找出的重要关系、风险与异常是什么
- 对应的图表是什么，图表说明什么
- 进行了怎样的建模，或做了什么实验分析 / 因果分析
- 最后得到什么结果或结论

补充约束：

- 这些内容必须基于本次真实执行过程来写，不得把未执行的分析步骤补成模板章节。
- 如果某类分析没有做，就不应硬写一个完整章节；最多只需明确说明“本阶段未执行”。
- 建议动作可以放在执行摘要中，不必单独拉出文末“业务解释”章节。
- 术语解释应尽量嵌入核心指标表、图下注释或正文，不再默认单独追加“名词解释”区块。

## 名词解释要求

每次正式交付，凡是出现以下类型词语，默认都要附一句简短解释：

- 统计学名词
  - `p_value`
  - `confidence interval`
  - `normality`
  - `ANOVA`
  - `ADF`
- 机器学习名词
  - `accuracy`
  - `precision`
  - `recall`
  - `F1`
  - `RMSE`
  - `R2`
  - `SHAP`
  - `PDP`
- 因果与实验名词
  - `DID`
  - `RD`
  - `IV`
  - `CUPED`
  - `uplift`
  - `CATE`
- 业务分析名词
  - `ARPU`
  - `ARPPU`
  - `retention`
  - `LTV`
  - `conversion rate`

解释风格要求：

- 一句话
- 尽量不用公式
- 先说“它是什么”，再说“怎么理解”
- 优先写在核心指标表、图下注释或正文段落中，而不是另起附录表格

## 数值解释要求

每个关键结果表格或图表旁边，都要预留“数值说明”区块。

标准格式：

- 指标名
- 本次值
- 指标含义
- 当前值代表什么
- 这次值偏好还是偏弱
- 需要结合什么上下文

### 示例

- `F1 = 0.66`
- 含义：综合衡量 precision 和 recall 的平衡
- 当前值代表什么：说明模型兼顾了查准和查全，但还不是特别强
- 这次怎么理解：如果 baseline 只有 0.55，那么 0.66 有明显提升；如果 baseline 已有 0.64，则提升有限

## 文风要求

- 默认中文
- 先结论后细节
- 避免只贴技术术语不解释
- 每个章节尽量回答“所以呢”

## 图表要求

- 图题必须为中文
- 图表解读必须结合图像本身和报告前文，不得只复述文件名、图表类型或脚本输出名
- 每张图下方至少要有两段自然语言：
  - 第一段：说明图里当前出现了什么情况
  - 第二段：说明这对业务、研究对象或决策意味着什么
- 图表解读应直接写观察到的情况和意义，不要写成“这张图围绕……展开”“帮助读者理解……”这类说明书式表达
- 如果图中出现英文指标、英文图例、英文坐标、英文缩写，或中文专业名词对基础读者有理解门槛，图下注释必须补充简短解释
- 多张图之后必须追加一段“图表总体解读”，把整组图的共同信息串起来
- 对 one-hot 派生图、单个 dummy 变量图、明显偏技术诊断的图，优先回溯到原始业务字段再决定正文表达方式

## DOCX 与 PDF 的差异化要求

## DOCX

- 适合可编辑、可批注、可继续修改
- 章节更完整
- 表格更详细
- 末尾不再默认追加附录表格

## PDF

- 适合固定版式分发
- 执行摘要更靠前
- 每页信息密度更高
- 图表和结论需要更凝练

## 输出文件命名建议

- `analysis-report-zh.docx`
- `analysis-report-zh.pdf`

如果是具体项目或 run，可命名为：

- `brfss-obesity-analysis-report-zh.docx`
- `brfss-obesity-analysis-report-zh.pdf`

## 大模型写正式报表时必须遵守的规则

- 默认中文输出
- 默认解释专业名词
- 默认解释关键数值的好坏
- 默认说明限制与风险
- 默认引用实际存在的 JSON / PNG / Markdown 工件
- 不得只复制模板文本，必须结合本次真实输出重写
- 图表章节不得保留“怎么看”“本图结论”这类模板化占位语
- 当前正式报告应以“内容清楚、证据可追溯”为先，不要为了版式完整虚构流程细节
