# 图表选择

## 当前定位

这份文档是“按分析问题选图”的参考，不是当前 skill 的图表治理流水线说明。

当前更常见的交付形态是脚本直接生成的 PNG，或在报告里给出应画什么图的文字建议。

不要默认假设存在图表候选池、图表评审 JSON、或统一 dashboard 体系。

## 选图先看问题，不先看图种

先回答你想让图解决什么问题：

- 展示分布
- 展示组间差异
- 展示两个变量关系
- 展示时间变化
- 展示漏斗流失
- 展示构成与贡献

如果问题没定义清楚，图越多越容易把人带偏。

## 常见映射

### 1. 单一数值分布

适合：

- 直方图
- KDE
- 箱线图

适用问题：

- 指标是否偏态
- 是否存在异常值
- 分布是否长尾

### 2. 类别 vs 数值

适合：

- 柱状图
- 箱线图
- 小提琴图

适用问题：

- 不同分组的均值/中位数差异如何
- 波动范围是否不同

### 3. 两个数值变量

适合：

- 散点图

适用问题：

- 是否存在明显正负相关
- 是否有分群、离群点、非线性迹象

### 4. 多个数值变量

适合：

- 相关性热力图
- 散点图矩阵

适用问题：

- 哪些变量成组变化
- 哪些变量值得继续深挖

### 5. 时间变化

适合：

- 折线图

适用问题：

- 趋势、季节性、断点、活动影响

### 6. 漏斗与构成

适合：

- 水平柱状图
- 堆叠柱状图

适用问题：

- 步骤转化与流失
- 构成占比与贡献变化

## 当前 skill 下的实际选图原则

- 优先使用原始业务字段，而不是 one-hot 之后的派生列
- 优先画能支持结论的图，不要为了“图丰富”而堆图
- 如果一个表就能说清楚，不必强行画图
- 对高基数类别，先聚合或截断，再决定是否作图

## 中文显示

如果要产中文图，优先使用系统已存在的 CJK 字体，例如：

- `Noto Sans CJK SC`
- `Source Han Sans SC`
- `PingFang SC`
- `Microsoft YaHei`

并确保：

- `axes.unicode_minus = False`

## 哪些图更适合作为诊断图

以下内容通常更适合诊断、附录或分析师复核，而不是默认放进正文主图：

- PDP
- 模型得分分布
- 编码后特征的技术性可视化
- 只对建模人员有意义、但对业务读者解释成本很高的图

## 如果当前环境不适合出图

不要假装存在“图表计划 JSON”这类稳定工件。

更合适的做法是：

- 在 Markdown 里写出推荐图种
- 说明每张图要回答的问题
- 标注对应字段和读者价值

## 建议叙述顺序

1. 背景或口径图
2. 核心发现图
3. 诊断或解释图
4. 风险与不确定性图

## 防护准则

- 图表服务于结论，不是装饰。
- 图越复杂，越要确认读者是否真的需要它。
- 不要把模型解释图直接升级成业务事实图。
- 没有稳定图形输出时，用文字说明替代即可。
