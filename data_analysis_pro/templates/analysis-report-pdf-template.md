# 中文 PDF 分析报表模板

> 用途：供 `pdf` skill 生成正式中文 PDF 分析报告时使用。
> 风格：固定版式、信息密度高、适合管理层和外部分享。

## 页面结构建议

- 页数建议：`6-12` 页
- 页面尺寸：默认 `A4`
- 默认语言：中文
- 字体要求：必须支持中文正常显示

## 1. 封面页

- 报告标题
- 分析对象
- 时间范围
- 日期
- 作者 / 系统

## 2. 一页执行摘要

这页必须回答四个问题：

1. 要分析什么问题
2. 本次实际做了什么
3. 发现了什么
4. 最后得到什么结果或结论

建议版式：

- 顶部：一句话结论
- 中部：本次分析过程摘要
- 下部：关键结果、结论和风险提示

## 3. 数据读取、数据情况与清洗

建议版式：

- 左侧：数据读取方式与当前数据情况
- 右侧：缺失、异常、重复和清洗摘要卡

摘要卡建议包含：

- 行数
- 列数
- 缺失列数
- 重复率
- 主要异常值提示
- 是否执行清洗
- 清洗后数据是否生成

## 4. 重要两字段关系图表与解读

建议按重要性从高到低展示本次重要的两字段关系。

每张图统一结构如下：

- 图标题
- 图本身
- 图说明
- 第一段解读：这张图当前展示了什么情况
- 第二段解读：这背后意味着什么

> 建议流程：先由脚本生成首稿与 `report_context.json`，再让 agent 输出 `chart_review.json`，最后由脚本回填到正式 DOCX / PDF。PDF 不建议直接人工改版式。
> 文风要求：直接写图中当前情况和背后意义，不要写“这张图围绕……展开”“帮助读者理解……”这类说明书式句子。

多张图之后必须补一段“图表总体解读”。

## 5. 建模 / 实验分析 / 因果分析

每类实际执行过的分析占 1-2 页，统一回答：

- 本次做了什么分析
- 为什么这样做
- 得到了什么结果
- 这些结果意味着什么

如果某类分析没有做，就不要硬写成完整章节。

## 6. 最终结果与结论

最后一页或最后一节应整合说明：

- 本次分析最后回答了什么
- 还有哪些问题没有回答
- 当前结论的主要限制是什么

## PDF 交付规则

- 不要把 PDF 做成“长网页截图”
- 图表标题和注释都必须为中文；术语解释应直接嵌入正文、表格或图下注释
- 每个关键数值旁边都要有一句“怎么理解”
- 如果没有某项指标，不要伪造占位结果
- 图表章节不要保留“怎么看”“本图结论”这类模板化小标题
