# Ebook → Markdown (one file per body chapter)

`scripts/ebook_to_md.py` splits an EPUB into `NN_<chapter title>.md` files — one per body
chapter, with every image kept. Chapter breaks and titles come from the book's own table of
contents (EPUB 3 nav doc, else NCX), so the split follows the book's structure instead of a
guess. A TOC entry owns the whole reading span up to the next entry, across spine
documents: calibre's one-page-per-file split stays one chapter. How Calibre itself resolves
chapters in EPUB/MOBI/AZW3/PDF is written up in
[`references/chapter-detection-calibre.md`](references/chapter-detection-calibre.md).

**Only the body is written by default.** Covers, copyright/CIP pages, 目录, prefaces
(推荐序/前言/自序), part dividers, indexes and other front/back matter produce no file.
Scholarly apparatus — 注释/Notes, 参考文献/References, 后记/Afterword, 词汇表/Glossary —
is body, not back matter, and is kept. Two things keep that lossless: `README.md` lists
every skipped page and why (未收录 section), and part names still reach the chapters as
`part:` in the front matter. Pass `--all-pages` when the user does want the front matter.

## Quick start

```bash
# default: writes <book folder>/<book title>/, body chapters only
python3 "<SKILL_DIR>/scripts/ebook_to_md.py" "book.epub"

# explicit destination（书库里定稿到那本书的 md/）
python3 "<SKILL_DIR>/scripts/ebook_to_md.py" "book.epub" -o "$BOOKS_ROOT/books/<uid>/md"

# always run this before reporting the result
python3 "<SKILL_DIR>/scripts/verify_output.py" "<outdir>"
```

`$BOOKS_ROOT` is the books repository root. Set it to the repo root before running the examples.

`<SKILL_DIR>` is the directory containing this SKILL.md. Requirements: Python 3.9+ and
`beautifulsoup4` (`pip install beautifulsoup4`; `lxml` is used when installed). If a
dependency is missing the script exits with the exact pip command — run it, do not hand-roll
a replacement.

If the user just says "转成 md", run the default form: the folder lands next to the book. Do
not ask for an output path unless they named one, or two books would land in the same place.

## Batch/inventory jobs

## Collections (套装、全集、大全集)

A collection EPUB (several books in one file) is split with `scripts/split_collection.py`
and a JSON split map — one folder per book, each with the normal chapter tree:

```bash
# 书库里先落批次暂存区，校验后 rename 进各卷的 md/（见书库方案 §7）
python3 "<SKILL_DIR>/scripts/split_collection.py" "合集.epub" -o "$BOOKS_ROOT/工作区/批次/<批次>/out" --map split.json
```

```json
{
  "collection": "鬼吹灯 8部全集图文版", "series": "鬼吹灯",
  "books": [
    {"folder": "鬼吹灯-精绝古城", "labels": ["鬼吹灯I精绝古城"]},
    {"folder": "三体-获奖感言", "labels": ["刘慈欣2018克拉克奖获奖感言"], "keep_marker": true}
  ],
  "skip": [{"label": "版权信息", "reason": "合集卷首页"}, "制作说明"]
}
```

- List the books **in reading order**: a book owns every page from its label up to the next
  book's label. The label is matched exactly (then by prefix) at the shallowest TOC level —
  needed when a book's title also appears as a section inside another book.
- `skip` = collection-level pages belonging to no book (covers, 版权, the collection TOC)
  and duplicate copies; they are left out and listed in the collection README (合集卷首/卷尾页)
  with the reason you give. A `skip` label must be a real TOC entry: a TOC-less page is
  auto-excluded as 合集卷首/卷尾页 anyway, and its autogenerated name (`章节 3`,
  `前置页 4`) cannot be matched — a skip on it fails the dry-run.
- Output per book is identical to the single-book script; a `<series>-合集说明.md` at the
  output root lists every book with its chapter count. A book's own title page never becomes
  a file unless the book sets `keep_marker`. Output options (`--no-images`, `--all-pages`, …)
  are the same as the main script.
- **Misaligned split documents** (the NCX anchors sit in the wrong documents, so every
  document's leading chapter is unowned — `audit_volume.py` LOW with per-document prefixes
  missing): add `--carry-doc-prefixes` to hand each document's prefix to the previous
  chapter, the same fix `scripts/carry_doc_prefixes.py` applies to single books
  (渡边淳一精华集: 60% → 98%).
- **Before splitting, dry-run the map** — `scripts/verify_map.py "合集.epub" --map split.json`
  writes nothing and exits 1 with the exact problem (label not found, order off, duplicate
  folders, a book owning no pages). Then split, then audit with `scripts/audit_volume.py`
  (see *Verify before reporting back*). Building a map from scratch — reading the TOC,
  choosing labels, skips, duplicates, folder naming — is written up in
  `references/collection-maps.md`.

## What you get

- `NN_<章节标题>.md` — one file per body chapter, numbered from `01` with no gaps, so the
  folder sorts the way the book reads. A leading chapter number is dropped from the file name
  when it merely repeats the index (`01 竞争优势：核心概念` → `01_竞争优势：核心概念.md`).
  Numbered sub-sections merge into their chapter: when the TOC lists `第一章 …` and then bare
  `01`/`02`… (or `一`/`二`…) entries one level down, those numbers are the chapter's own
  subsections, so the chapter comes out as a single file. A TOC entry also owns the
  TOC-less spine documents that follow it, so calibre's title-page + prose split is one
  file instead of a 35-character stub plus `前置页` files.
- YAML front matter per file: `title`, `part` (the 第N部分 it belongs to, when the book has
  parts), `author`, `publisher`, `date`, `language`, `source`, `chapter`.
- `README.md` — body table of contents with the part structure as bold lines, chapter and
  image counts, and the 未收录（卷首/卷尾页）list of everything that was skipped and why.
- `images/` — every image the kept chapters use, referenced relatively
  (`![](images/00013.jpg)`) so each file renders on its own. Unreferenced images are pruned.

## Options

| option | use when |
| --- | --- |
| `-o OUTDIR` | the user named a destination, or several books must not share one folder |
| `--title NAME` | the output folder should use a cleaner name than the embedded title |
| `--all-pages` | the user wants front/back matter too (推荐序、版权页、目录… restored) |
| `--drop REGEX` | extra exclusions by title, repeatable: `--drop '^第.部分'` |
| `--keep REGEX` | a body section is named like front matter and got filtered — force it back, repeatable (e.g. 金字塔原理's `序言的结构`, or a chapter literally titled `^致谢$`) |
| `--no-merge-sections` | numbered sub-sections (01/02…, 一/二…) should stay separate files instead of merging into their 第N章 parent |
| `--no-untoced` | do not write standalone TOC-less pages; a TOC entry still keeps its continuation documents |
| `--no-images` | the user wants text only |
| `--no-frontmatter` | the user wants clean Markdown without YAML |
| `--heading-recovery off` | text should come out untouched, with no inferred headings |
| `--no-index` | no README.md |

## Judgement calls

- **The body filter is title-based.** Numbered chapters always survive (`01 …`, `第1章 …`,
  `附录1 …`), and unknown titles default to body, so nothing is dropped silently — but a
  preface with an unusual name can slip through, and a chapter that starts with a word like
  目录 can be dropped. Check the 未收录 list in README.md after every run and tell the user
  what was excluded; use `--all-pages`, `--drop`, or a manual rename when the filter got it
  wrong.
- **Scholarly apparatus is body; index and acknowledgments are not.** `注释`/`Notes`/
  `Endnotes`, `参考文献`/`References`/`Bibliography`, `后记`/`Afterword`/`Epilogue`,
  `词汇表`/`Glossary` are reading text for a citation-heavy book and are kept by default.
  Dropping them as back matter used to cost 20–30% of a monograph (论人类不平等的起源和基础
  70.8%, 这次不一样 76.3%, 芯片简史 79.7% — 26.5k/38.4k/55.5k chars sat in the dropped
  pages). `索引`/`Index` is page locators and stays out; `致谢`/`Acknowledgments` is thanks,
  not reading text, and stays out. To omit apparatus for a book that really should not
  carry it, pass `--drop '^注释$'` (or `^参考文献$`, `^后记`). A final chapter named
  `Epilogue`/`后记` is now body without `--keep`; `结语`/`结论` always were.
- **A TOC anchor sits on an empty title page.** Calibre's split files often put the chapter
  title on `split_013` (no text) and the prose on `split_016`; the TOC-less pages in
  between are the chapter, not standalone `前置页` files. `build_units` attaches them to
  the preceding TOC entry when they are empty, repeat its title, or carry prose
  (重新定义公司: 29 files / 71.6% → 13 files / 99.8% with the usual `--keep` for prefaces).
  A short TOC-less page that starts a new standalone heading (编者注, a publisher
  colophon) stays separate so the title filter / `--drop` can see it. If a book still
  splits one chapter across documents, check `build_units` — not `doc_units.py`.
- **Footnote text appears twice** (audit HIGH, 芯片战争 133.2%): a note-number icon has
  `alt` equal to the `<aside epub:type="footnote">` prose, so rendering it as
  `![note](images/…png)` writes every note twice. Images inside a noteref link (or with a
  `footnote` class) now render with an empty alt, and a long alt that already appears in
  the page text is dropped; short captions stay. An audit over ~115% with the note text
  present twice is this shape — check `img[alt]` against the nearest `aside`.
- **A publisher/colophon page after the last chapter**: `产品经理│… 责任编辑│… 官方网站…`
  is not a continuation. A short TOC-less page with two or more such markers is excluded
  and listed as 版权/出版信息页 (论人类不平等的起源和基础's 果麦 page). If a colophon uses
  different words, add them to `COLOPHON_RE` or use `--drop`.
- **Book has no TOC** (nav doc and NCX both absent): the script warns on stderr and emits one
  file per spine document. Fine when the spine is chapter-granular (common in converted
  books); when the whole book is a single spine document you get one file — say that the book
  carries no chapter structure instead of inventing boundaries. Do **not** pass `--no-untoced`
  there: with no TOC entries there is nothing to keep, so it would refuse to run.
- **A chapter file is huge (a whole part)**: the source TOC really is that coarse. Heading
  recovery never splits a file, so a finer split does not exist for that book — tell the user;
  do not fabricate one.
- **Headings**: `<h1>`–`<h6>` are used as-is when the book has them; otherwise headings are
  inferred from CSS (font size first, then layout: alignment, indentation, spacing) and mapped
  onto `##`/`###`/… so each chapter's own title stays the only `#`. Inferred headings are the
  risky part of any converter — spot-check the smallest and largest files.
- **Part dividers**: entries like `第N部/篇/卷`, `上/中/下部/篇/册` and `书名上册` are part
  dividers: they set `part:` for the chapters that follow and only become files themselves
  when the page carries real text (some epubs pack a whole part into one document labelled
  `上部 面壁者` — dropping it would lose that text; a title-only divider page still produces
  nothing).
- **TOC anchors that land on footnote markers**: a fragment like `part0023.xhtml#ch1` often
  points at the inline `<a>` of the `[1]` footnote mark inside a heading. The slicer climbs
  to the nearest block element before cutting; without that, chapters came out as
  3-character stubs.
- **Text volume**: with `--all-pages` a faithful run carries ~100% of the raw EPUB text
  (Markdown markup adds a fraction of a percent); the default body-only run carries ~94–97%,
  the rest being front/back matter. `scripts/audit_volume.py` compares text and prints LOW /
  HIGH / NOT CONVERTED. It does not count text embedded in scanned images. In collection mode
  it allocates raw text by spine document, so a single XHTML document shared by two books can
  create a false LOW/HIGH. For either case, check the README exclusions, image links, and
  actual TOC-unit spans before deciding text was lost; report only unexplained gaps.
- **Malformed XML**: some epubs ship a broken OPF/NCX (an unclosed `<!--` comment in
  盐铁论's `content.opf`, a mis-encoded NCX, or an undeclared XML prefix). The parser repairs
  what it can. If it still fails, try a standard Calibre EPUB→EPUB repackage in a temporary
  location, then run the normal converter and audit on that EPUB while keeping the original
  untouched. If Calibre also fails, report the file and line rather than hand-rebuilding it.

## When output looks wrong

- **One chapter became several tiny files** (`02_第一章…`, `03_第一章…`, `04_前置页 17`):
  the TOC anchor is on an empty title page and the continuation docs were not attached.
  `build_units()` is the place to look; the regression is 重新定义公司 29 files / 71.6% →
  13 files / 99.8%. If the anchor page itself holds only a chapter number / `PART II`,
  that is the `doc_units.py` case below, not this one.
- **Audit HIGH and the same note prose appears twice**: an image `alt` copies a footnote
  aside (芯片战争 133.2%). `_clean_alt()` suppresses noteref/footnote alt and long
  duplicate alt; if it comes back, check that hook.
- **A footnote marker comes out as `[[1]]()`**: a link with a bracketed label points at an
  excluded page. `MD_LINK_RE` unwraps it to plain `[1]`; if the empty target reappears,
  that regex is what regressed.
- **A chapter file is a few characters long**: a TOC fragment landed on an inline anchor
  (usually a footnote mark). The slicer climbs to the nearest block element; if stubs
  reappear, that climbing is what regressed.
- **A whole 部/篇/卷 is missing**: a part-titled unit probably swallowed it. Part dividers
  are only dropped when their page carries no text — re-check that rule, not the TOC.
- **Files from an earlier run linger after a re-split**: chapter numbering shifts, so old
  files can look valid. The script prints the leftovers; delete only files the README does
  not link (parse the `](` at the end of the line — real titles contain `)` and `（）`,
  so a glob or a naive regex eats good files).
- **A 篇/章 file repeats text its sub-section files already hold** (audit ratio over ~115%):
  a TOC entry whose page carries no `#fragment` used to take its whole document while each
  sub-section took its own span — each block landed in the parent file and again in a child
  file (银河帝国 audited at 197%). No-anchor entries are now bounded at the next entry's
  anchor, and entries sharing one anchor leave the span to the run's last entry; if
  duplication comes back, that bounding is what regressed.
- **Several TOC labels share one anchor, or labels point at nothing** (百年孤独: 20 章
  labels, most pages anchored `#None`): blocks of labels collapse into one file and later
  chapters lose their names. When the spine is chapter-granular (one document per chapter —
  check the first line of each `content_docs()` entry), rebuild the units
  document-per-chapter in reading order instead of trusting the TOC; recipe in
  `references/broken-toc-anchors.md`. If the spine is not chapter-granular, report that the
  book's anchors are broken instead of inventing boundaries.
- **Files exist but hold only the start of their page** (audit LOW with no front matter to
  blame; calibre wraps the anchor in a small inner `div` and the prose continues after it):
  the last entry of a page now takes everything from its start to the end of the document,
  climbing out of inner wrappers (`高效能人士的七个习惯` — its 最后访问/索引 pages were ~5%
  of their documents before that fix). See `references/broken-toc-anchors.md`.
- **Ratio LOW and the 未收录 list cannot explain it, with per-document coverage showing the
  text *before* each document's first anchor missing** (calibre `index_split_NNN` docs
  misaligned with the anchors — 邓小平时代 73.8%): the previous chapter's tail plus its
  endnotes sit in the next document's prefix, owned by nobody. Re-run with
  `scripts/carry_doc_prefixes.py` (hands every prefix to the previous chapter as a
  `merge_children` source), then re-verify and delete the earlier run's leftovers. See
  `references/broken-toc-anchors.md` §6.
- **A 40-char `前置页 N` file with just an image, or a piracy stamp page near both ends**
  (`本书由公众号…整理`): untoced junk pages that the title filter cannot name. Re-run with
  `--drop` patterns from `references/broken-toc-anchors.md` §7.
- **Chapter count far below the book's own Contents page, with many 10–50 character files**
  (The Lever of Riches 3 chapters of 12 at 29.6%; Who Gets What 23 files for 12 chapters at
  87.7%): the NCX points at the page *before* the body — a part divider, a `CHAPTER ONE`
  ornament page, or the bare `10`/`11` number page — so each anchor's own span holds no
  prose and the body goes unowned. Try the default run first: an empty anchor page with the
  prose in the next document is now attached by `build_units()` (see the first bullet in
  this section). When the anchor page itself carries the chapter number/part divider, or
  the TOC has dozens of sentence-long `filepos` entries, build a page map from the book's
  own Contents page and run `scripts/doc_units.py BOOK.epub -o OUT --map pages.json`; the
  recipe and the map format are in `references/broken-toc-anchors.md` §8.
- **Text volume looks low**: run `audit_volume.py`, then read the README's 未收录 list. Only
  when the two together fail to account for the gap is there a bug — see the failure
  modes listed above.

## Verify before reporting back

When you change the converter itself, run `python3 "<SKILL_DIR>/scripts/selftest.py"`
first: throwaway EPUBs for the continuation, footnote-alt, colophon and apparatus rules;
it should print `all selftests passed`.

1. `verify_output.py <outdir>` — prints file/character/image counts and problems (broken links,
   missing or orphan images, identical files). Exit code is 1 when problems exist; fix or
   explain them before finishing. For identical files, check whether the source repeats a
   chapter/document or whether duplicate TOC entries point to the same source span. Preserve
   faithful source repetitions and record why they remain; do not delete them just to silence
   the verifier. A "broken link" whose target is ordinary prose (a citation, a publisher
   line) or a formula (`1 −*P*[Y~*i*~= 1|X~*i*~]`) is usually literal text in the source.
   The verifier only checks targets that carry a file extension (`.md`, image types), so
   that stray markdown is not reported; a reported broken link names a file, so check the
   source before "fixing" it. A file the
   notes list calls `only N chars (front matter page?)` is the untoced junk of
   `references/broken-toc-anchors.md` §7: drop it with `--drop` rather than shipping a
   33-character chapter.
2. `audit_volume.py "book.epub" -o <outdir>` (add `--map split.json` for a collection) —
   compares converted text against the EPUB. For MOBI/AZW3, audit the temporary EPUB produced
   by Calibre and separately spot-check that conversion against the original. LOW is not
   automatically a bug: a long 导读 or 致谢, image-only pages, or books sharing one spine document
   can explain it. Read 未收录 and, for shared-doc collections, compare TOC-unit spans before
   treating the ratio as a loss.
3. Read the first ~20 lines of one mid-book chapter and of the smallest file; confirm the
   images resolve and the headings look like headings, not stray sentences.
4. Report: output folder, chapter count, image count, and — from the 未收录 list — which
   pages were left out, so the user can ask for them back.

## Non-EPUB sources

`.mobi` and `.azw3` are refused by the script. Convert them to a temporary EPUB with Calibre,
then run the normal single-book or collection workflow. Read
[`references/mobi-azw3.md`](references/mobi-azw3.md) for commands, provenance, missing-guide
failures, and the no-TOC case. The format-specific rules Calibre uses (EPUB nav/NCX, MOBI
guide/INDX, KF8 embedded EPUB, PDF outline then typography) are summarised in
[`references/chapter-detection-calibre.md`](references/chapter-detection-calibre.md).

`.pdf` is also refused. PDF→EPUB conversions are lossy: reading order and headings can be
rough, so verify more carefully and say which parts look unreliable rather than presenting
them as the book's structure.

## 回归检查

改动 `ebook_to_md.py` 或 `doc_units.py` 后，先跑：

```bash
python3 "<SKILL_DIR>/scripts/selftest.py"
```

它用临时目录里生成的 EPUB 覆盖四条规则：空标题页的锚点续接、脚注 alt 重复、章末版权页、附录保留与索引丢弃。末行应为 `all selftests passed`。

再用一两本有代表性的书跑 `ebook_to_md.py`、`verify_output.py`、`audit_volume.py`，确认三件事：

1. 章节数与目录条目对得上。
2. `audit_volume.py` 的正文比落在本书 README 记录的区间内。异常时先看是不是前后置页被算进正文。
3. 抽查一本中段章节与最小章节的开头，图片能显示，标题像标题。

不同书的比值差异很大，注释多的学术书可能天然只有 80% 左右。把每本书的实际比值与未收录清单写进 README，比记一个全局阈值可靠。
