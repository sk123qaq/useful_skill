# 视频解说（外语片 → 中文解说成片）

把一部外语影视的长视频，做成"中文解说 + 保留原片经典原声"的成片。典型片长约 10 分钟
（7–13 分钟都算合格），原片可以是 25–50 分钟的一集剧或一段片子。

## 三条铁律

1. **音色先定，再动工。** 先问用户有没有指定音色；没有就用 `scripts/voice_audition.py` 生成一批样音
   （同一段 ~20 秒解说词、同一语境指令、只换音色）让用户听选，也可以给 3 秒参考音频走音色复刻。
   音色定错 = 全片作废重出。
2. **上来直接讲。** 不要黑底片头卡、不要顶部标题条、不要底部信息条（除非用来盖水印）、不要名牌卡。
   **t=0 就要有人声解说**，第一句就是钩子：背景一句 + 冲突一句 + 悬念一句，把"为什么值得看下去"讲掉。
   画面直接用原片自己的片头（含剧名卡/主题音乐），解说压在上面——这是本项目验证过最抓人的开场。
3. **时长是软指标。** 用户说"10 分钟"通常意思是 7–13 分钟都行。绝不为凑时数灌水或砍故事；
   解说词长度是主变量，片段长度跟着解说词走。

## Prerequisites

- `ffmpeg` / `ffprobe`（必须带 `libx264`、`libass`、`drawtext`，带 `h264_vaapi` 更好）、`python3`（脚本只用标准库，无 pip 依赖；**只有封面 `cover.py` 要 Pillow**=`python3-pillow`）
- 渲染默认 **GPU 编码**：`render.py` 走「软解 + CPU 滤镜 + `h264_vaapi`」，需要 `/dev/dri/renderD128`；
  节点缺失或编码失败会自动回落 `libx264`。两条路都能出片，实测差距见 Pitfalls。
- ASR：默认 `scripts/asr_qwen.py`（Qwen3.0 ASR `qwen-audio-3.0-asr-flash-filetrans`，经 `~/.hermes/skills/media/qwen-asr` 调用，**返回句级/词级时间戳**；key 用 `$DASHSCOPE_API_KEY` 或 `~/.config/qwen-asr/api_key`）
- TTS：默认 `~/.agents/skills/stepaudio-tts`（StepAudio 2.5，默认音色 `elegantgentle-female`）
- 冒烟测试：`sh tests/run.sh`（用 lavfi 假素材 + 离线桩，不花钱、不联网，验证这条链今天还跑得通）
- 换模型的两种情况（本 skill 留了余地）：
  - **ASR 返回词级时间戳**（当前默认的 qwen 就返回）→ `probe.py --transcribe` 直接按句级时间戳建立台词表，第 2 阶段的“估时 + 短窗探测”（2b/2c）缩为抽查。
  - **TTS 返回逐词字幕**（`--subtitles` 之类）→ 解说字幕直接用真实时间戳，跳过 `timeline.py` 的停顿吸附。
  - 换了模型只需改脚本参数（`--asr` / `--tts` / `--voice`），流程不变。

## Procedure

### 第 0 阶段：定音色（音色先定）
```bash
python3 scripts/voice_audition.py --text-file sample.txt --out voice_samples   # 13 个候选音色各出一段
python3 scripts/voice_audition.py --list
```
**完成标准**：用户明确选定一个音色 id（或给了 3 秒参考音频）。之后所有 `--voice` 都用它。

### 第 1 阶段：侦察（5 分钟，别跳）
```bash
ffprobe -v error -show_entries format=duration -show_entries stream=codec_type,width,height,r_frame_rate \
        -of default=noprint_wrappers=0 原片.mp4
mkdir -p work && cd work
ffmpeg -v error -i 原片.mp4 -vn -ac 1 -ar 16000 -b:a 64k full.mp3
# 抽帧看：构图、烧录字幕位置、水印位置（片头/片中/片尾各抽几帧拼图）
for t in 3 20 30 60 120; do ffmpeg -v error -y -ss $t -i 原片.mp4 -frames:v 1 -vf scale=400:-1 f_$t.png; done
ffmpeg -v error -y -pattern_type glob -i 'f_*.png' -vf tile=5x1 sheet.jpg
# 有外挂字幕就顺手确认它与视频对齐（对齐了就不用全片 ASR，直接用 SRT 建台词表）
```
**完成标准**：一句话能答出 ① 原片是否自带烧录字幕、在画面什么高度 ② 水印在哪几条 y 带
③ 音轨总时长 ④ 有没有时间轴对齐的外挂字幕。这四条决定解说字幕 MarginV、要不要底部信息条、台词表怎么建。
**①要量出"字幕带顶"的具体 y 值**（原尺寸，别在缩放图上量）：有烧录字幕时它是承载带 `--sub-band` 的输入，
`TOP = 字幕带顶 − 渐变高 − 36px`。量法：抽几帧带对白的原片帧，逐行统计底部区域的亮像素，取所有帧里
最高的那一行（实测 S1E1 是 y1848，中文行 1848–1962、英文行 2004–2076）。
要定字幕观感就顺手跑一次 `python3 scripts/style_preview.py --frame f_30.png --out /tmp/preview`
（B/C/D 四种样式并排，别靠想象选）。

### 第 2 阶段：台词时间轴（本流程的地基）
```bash
# 2a 分块转写建台词表（5 分钟一块，并发 ≤ 4；qwen 给句级时间戳 → 每行一句、起止是真实句时间）
#   自带「尾部覆盖检查」：长块 ASR 会在块尾吞句——任一块转写止于块末 >8s 前，
#   自动用 ≤12s 短窗补测空缺段并合回台词表（S3E05 事故：全剧最后一句
#   "Yes, Minister!" 被吞成 "Yes."，末句终点少 1.5s → 彩蛋 pe 短 1.5s → 成片
#   把最后一个词切掉半截）。窗要短：ASR 对「句尾混音乐」的窗有方差，4s/12s 窗
#   能拿到被吞句尾、20s 窗同样漏；补测没捞回时会明确告警（见「常见异常与自检」）。
#   --tail-gap 调阈值，--no-tail-fix 关掉（不推荐）。
python3 scripts/probe.py --source 原片.mp4 --transcribe --chunk-sec 300 -o transcript.tsv -j 4
# 2b 粗定位：在若干时间点抽短窗做 ASR
python3 scripts/probe.py --source 原片.mp4 104.5 180 282.1 548.3 --dur 2 -j 4
# 2c 金句精确到 ±0.2 秒（能量谷点定句 + 短窗 ASR 复核），结果直接写进 plan.json
python3 scripts/probe.py --source 原片.mp4 --pin 105.0 --expect "你能保守秘密吗"
#   → [105.18, 107.42]  "你能保守秘密吗？"
# 2c' 最后一个彩蛋（收尾梗/标题梗高发）必须把搜索窗开到 pe 之后：台词表末句可能
#     就是残句（长块吞尾），"下一句起点 − pe" 判据对全剧最后一句没有下一句。
python3 scripts/probe.py --source 原片.mp4 --pin 1720.4 --window 6 --expect "Yes Minister"
```
所有探测结果缓存在 `--keep` 目录（键 = 片源 mtime/区间），重跑免费。
**完成标准**：每条彩蛋句都有 `[起点, 终点]`，且窗口单独抽出来 ASR 确认首尾都是整句。
**末个彩蛋加一条**：台词表末句必须覆盖到剧末人声（2a 的尾部补测说了算），且用
**越过 pe 的窗外 ASR** 确认整句在 pe 处结束——「下一句起点」判据对全剧最后一句
没有下一句、会 vacuously 通过（S3E05 三道校验同时漏掉它的原因）。

### 第 3 阶段：定节拍 + 写解说词
- 先排 8–12 个叙事节拍（背景 → 冲突 → 反转 → 高潮 → 讽刺收尾），每个节拍对应一段源片画面。
- 标出 8–16 处**原声彩蛋**（名场面/金句），每条给出 `[起, 止]`。
  **止点** = 句末 + 0.35s；**末个彩蛋例外**：它的句末以「补测后的台词表 / SRT 末行 /
  窗外 ASR」三者一致为准——全剧最后一句（收尾梗、标题梗）最容易在分块 ASR 里被吞
  半截，也是唯一没有「下一句」可以核对的彩蛋。
- **第 0 个节拍是钩子**：一句背景（哪一年/什么事）+ 一句冲突（谁跟谁对着干）+ 一句悬念（这集翻在哪）。
  这三句在 t=0 就开始念，念在原片的片头画面上。
- **钩子念完原片只留 2 秒**（`--fixed-tail 2.0`，timeline.py 默认）：没人声的时候别让
  演职员卡/剧名卡拖节奏，片尾 fixed 段（收尾解说）同理。要保留某张卡（比如剧名卡），
  就把 fixed 终点写到它之后——脚本只在"解说完还有富余"时才压缩，绝不越过 fixed 终点。
- 每段解说词的目标时长 = 该片段长度 − 彩蛋尾巴 − 0.3 秒；按 4.4 单位/秒估算字数
  （单位 = 汉字 + 字母 + 数字，**字母要算**：CMG 会被逐字母念出来）。
- **每条彩蛋前的最后一句解说必须是它的铺垫**（观众听不懂这句为什么好笑，就是因为少了它）。
- **语速全片统一**（4.4 单位/秒），不要做"高潮快、收尾慢"——听感难控、返工更贵。
- 定节拍、选彩蛋、写解说词这类判断，先把候选（节拍表/彩蛋窗口清单）**写进文件再推理**：
  推理本身会留在上下文里被后续每一次调用重读，先落盘可以只把结论留在上下文里。
**完成标准**：每条彩蛋都能指着解说词说"上一句就是它的铺垫"；解说词总字数 ≈（目标片长 − 原声总长）× 4.4。

### 第 4 阶段：校验计划（1 分钟，省掉一轮返工）
```bash
python3 scripts/validate.py --plan plan.json --narration-dir narration --audio-dir norm \
        --source 原片.mp4
```
它复用 `timeline.py` 的求解逻辑，所以校验的就是真实剪辑：片段装不下解说、彩蛋窗太短、段名打错、
原声窗越界、解说窗重叠、开头没人声、末镜 <1.5 秒、总时长跑偏都会当场报出来。
**配音前**也能跑（`--stage plan`：只查结构与段名），**配音后**再跑一次（默认 `--stage cut`）。

### 第 5 阶段：配音（先 lint 再 pilot 再全量）
**本阶段是机械阶段，派子代理跑**：把 5a/5b 两条命令、下面的「完成标准」、`narration/` 的段数填进 brief
（模板 `references/subagent-brief.md`；为什么外包、父代理怎么接，见下文「阶段分工」一节）。
```bash
# 5a 文本体检（秒级）：空段/过短/子句无停顿/大数字，配音前就报出来
python3 scripts/lint_narration.py --dir narration            # 只有 ERROR 才退出 1
# 5b 配音 + 校验（语速由 pilot 标定，其他参数取 profile.json 的默认值）
python3 scripts/narration.py --dir narration --audio-dir audio --out norm -j 4
```
脚本对每段做四件事：合成 → **ASR 回读校验完整性**（失败重试 3 次）→ **吐字率/停顿预算归一** → **电平归一**；
并产出两份凭据：`audio/.meta.json`（内容指纹，音色/指令/文本/speed 一变就重合成）和
`norm/manifest.json`（哪几段**验过**、时长、sha1）。`timeline.py` 只认 manifest 里 verified 的段——
半成品进不了剪辑。调某一段用 `--only n07 --force`；`-j 4` 并发把 35 段从 40 分钟压到 ~12 分钟。

**`--profile`（默认 skill 根目录的 `profile.json`）**：跨集复用的参数——音色、指令、语速、
电平、`--gap` 默认值——集中在一处，换集不用每次手打一长串。命令行显式参数永远优先。
音色与 profile 不一致时自动忽略 profile 里的 `speed`（语速是音色相关的，不能套用）。
换音色、换一批解说词后：`--recalibrate` 重新标定，再把新值写回 `profile.json`。

**语速标定走 pilot（默认 5 段真实解说）**：旧做法用固定探针句，探针句的停顿与真实解说不同，
实测偏约 0.1 单位/秒，于是"全量 → 发现偏差 → 再全量"白跑一轮（第六集就是这么浪费的）。
现在按单元长度分位取几段**真正要配的解说**，在起点 speed 下各合成一次，取净吐字率中位数
一步算出全局 speed；只做 k 次 TTS、不做 ASR 回读，样本是 `.pilot_*.mp3`，不进 manifest。
来源优先级：`profile`（同音色同指令）> `.pacing.json` 缓存 > 已有 mp3 反推 > pilot > 3 句探针兜底。

语速一致性靠三个参数，别只调一个：
| 参数 | 含义 | 为什么需要 |
| --- | --- | --- |
| `--target-cps 4.4` | 整段节奏（单位/秒，**含停顿**） | 决定总时长，`timeline.py` 按它排镜头；解说词按它估字数 |
| `--target-artic 5.35` | **净吐字率**（单位/发声秒，**不含停顿**） | 听众感知的"语速"是这个；必须 > `--target-cps`，差额就是停顿预算 |
| `--max-run 4.0` | **最长连续发声**（秒） | TTS 会把几句话连成一口气。超了就在段内最深的能量谷点插停顿。取 4.0 是因为解说的天然一口气多在 2.2–3.3s，2.8 会在正常句子上反复开火（而它挑的是"最安静的谷点"、不是语法边界）；4.0 只兜真长跑 |
| `--target-db` | 净发声电平 RMS | 配合 `--level-mode speech` 才真正生效 |

**旧版只归一整段节奏，是"语速忽快忽慢"的根因**："说得快但停顿多"和"说得慢但不换气"在
`单位/整段时长` 这个指标下得分相同。实测一集 34 段：整段节奏全部 = 4.40，而净吐字率散布 4.68–6.11
（极差 1.43，CV 6.3%）。改成归一提字率后同样这批素材极差 0.55、CV 1.8%。
`--speed` 是**全局唯一值**（pilot 标定 + 缓存到 `<audio_dir>/.pacing.json`），残差全部交给 `atempo`；
**不要逐段给不同 speed**——speed 连重音、语调、停顿位置一起改，是音色质感不一致的来源。
⚠ `--target-db` 的起步值在 `profile.json` 里，**换素材必须实测重校准**（见第 6 阶段 calibrate）。

**完成标准**：表格里每段 `吐字率X.XX→5.3x`（差值 ≤0.1）、`连续发声 ≤ --max-run`、
`atempo` 落在 0.9–1.12、`cov ≥ 0.90`；结尾三行汇总给出吐字率极差/CV、连续发声上限、总时长。
`repace()` 写完每个 wav 会用**独立 silencedetect 回读**自检（净吐字率/总时长/最长连续发声），
任一项超容差就抛错并把该段的半成品**删掉**（不会留在 `norm/` 里被 timeline 当有效输入）。

### 第 6 阶段：剪辑 + 混音 + 合成
**本阶段是机械阶段，派子代理跑**：6b–6e 连跑；但 6d 若报「原声提升被限到 +NdB」或「解说要动超过 2dB」，
先停下把两个增益回报给父代理，由父代理定了再渲染（增益是听感判断，不外包）。
```bash
# 6a 计划校验（见第 4 阶段）
# 6b 求解时间轴 + 解说音轨 + 双语字幕 + 自检文档，一步到位
#    镜头切点由 timeline.py 自己检测并写到 out/cuts.txt（阈值 --scene 0.35）；
#    不要手工跑 ffmpeg 的 metadata=print 去造 cuts.txt——那种格式不是它要的输入。
python3 scripts/timeline.py --plan plan.json --audio-dir norm --narration-dir narration \
        --source 原片.mp4 --out-dir out --track \
        --dlg-srt 原片.srt --dlg-skip 9,10,11,12 \
        --fixed-tail 2.0 --narlow-last 6 --doc-title "《片名》S1E3 中文解说"
# 6c 行首标点归位（在 timeline 之后、渲染之前；timeline 每重跑一次这个必须重跑一次）
python3 scripts/fix_subs_punct.py out/narration.ass --manual manual.json
# 6d 响度 A/B 校准（换素材必做）：拿 out/narration.wav 与原片比，给出两个增益
python3 scripts/calibrate.py --plan out/resolved.json --narration out/narration.wav --source 原片.mp4
# 6e 合成（默认安全替换：先写 <out>.part.mp4，校验通过才替换成品并留 .备份）
python3 scripts/render.py --source 原片.mp4 --plan out/resolved.json --narration out/narration.wav \
        --ass out/narration.ass --out 成片.mp4 \
        --volume-orig +9dB --volume-narr -1.5dB     # 用 6d 给的数
#    编码默认 GPU（vaapi）；只有要强制纯 CPU 时才加 --encoder x264
```
**默认不带任何标题/片头卡**（`--title` 不填就没有；要的话 `--title "…" --title-until 8` 会在 8 秒后淡出，
默认连衬底都不铺）。`--intro-card` / `--name-plate` 是特殊场合的选项，常规出片不用。
**原片自带烧录字幕（中英双语压在画面底部）时，用承载带而不是把解说字幕往上让**：
```
--sub-band 1752 --sub-band-fade 60 --sub-band-accent 0xD8B26A
```
黑条从 y1752 铺到画面底边，只在解说窗内出现；原声窗里原片中英字幕完整回来——任何时刻只有一种字幕。
TOP 由第 1 阶段量到的「字幕带顶」反推：`TOP = 字幕带顶 − 渐变高 − 36px`（S1E1 字幕带顶 1848、渐变 60 → 1752）。
**双语字幕形态**：白色=解说、黄色=对白（`&H0000FFFF`），同字体同字号同位置，只靠颜色区分；
两类字幕时间上天然互斥（解说遮蔽区与原声全音量窗互补），不会叠字。原声窗 = 每段时长减去解说遮蔽区的补集，
自动覆盖 fixed/punch/blocks 三种条目；解说窗重叠会自动合并并告警。
**渲染期间绝对不要直接写成品路径**：mp4 在写完之前没有 moov 索引，用户此时打开就是"文件损坏"。
`render.py` 默认写 `.part.mp4` → 校验时长 → **抽 3 段试解码** → 原子替换 + 保留 `.备份`。
时长对不代表画面好：两个渲染进程同时写同一个 `.part.mp4`，会产出"时长分毫不差、NAL 全错"的坏片
（S1E1 实测解码错误率 99.7%），所以替换前那一步试解码是必须的。同理，**杀渲染要杀进程组**：
`bgrun.sh` 只记了包装 shell 的 pid，`kill` 它之后 `render.py`/`ffmpeg` 会变成孤儿继续写 `.part.mp4`——
先 `ps` 找到真正的 python3/ffmpeg pid 再杀，或干脆等它跑完。`render.py` 现在也有 `.part.mp4.lock` 双写入锁。
**闪避**：`--duck threshold=0.05:ratio=12:attack=15:release=400`（解说一响原声压约 12 dB，
一停立刻抬起）——这是"解说清楚、原声仍可辨"的关键，也是**必须**保留的默认行为。
三条边界规则由 `timeline.py` 自动执行：**①不掐句**（彩蛋窗以整句收尾）**②吸附镜头切换**
（末端落在切点前 0.05s）**③末镜至少 1.5 秒**。

### 第 7 阶段：核对 + 交付（渲染后只有三步）
**本阶段是机械阶段，派子代理跑**：verify 红了它只回报报错原文；红在哪、是稿子问题还是工具误报，由父代理判。

## 阶段分工：哪些交给子代理

**要动脑的留在主会话**：理解剧情、定节拍、写解说词、选彩蛋窗口、判断验证结果。
**机械的交给子代理**：第 5 阶段（配音）、第 6 阶段（时间轴/渲染）、第 7 阶段（质检）——
这些阶段跑的是固定命令，不需要剧情上下文，交给子代理可以让主会话不被几十段配音的
进度输出和日志刷爆，子代理那边也是一次全新的上下文。

写法：把要跑的命令、输入输出路径、验收标准写进一个 brief 文件（模板见
[`references/subagent-brief.md`](references/subagent-brief.md)），用 subagent 工具派下去，
**父代理不轮询**——它完成时本会话会被唤醒。子代理只回报"命令跑完了、指标多少、产物在哪"，
**不改写解说词**（要改稿先回报，由主会话决定）。

**后台等待**：能在前台用足够大的 timeout 跑完的，就直接前台跑；要同时做别的事才用后台：
```bash
sh scripts/bgrun.sh <名字> <命令> [参数...]     # 启动，写 <名字>.pid / <名字>.log
# …父会话去干别的…
sh scripts/bgwait.sh <名字> [超时秒=1800] [轮询秒=10]
```
`bgwait.sh` 退出码 = 任务自己的退出码，超时返回 124 并回显日志尾部（不会假装成功）。
⚠ **不要用 `pgrep -f` 判断进程是否结束**：它会匹配到发起等待的 shell 自己，循环永远不退出
（第六集白等过 12 分钟）。`bgwait.sh` 只看自己的 pid 和 `.rc` 文件。

### 第 8 阶段：封面（4:3 + 3:4，成片之后）
**默认先问用户：底图用成片里的哪一帧？**（给个时间轴位置，如 `8:09`。）
用户没主意就先出一张候选帧拼图让他挑，再拿他选的位置做；一帧底图出两种规格。
```bash
# ① 候选帧拼图（每格烧时间码，划走挑一个位置）
python3 scripts/cover.py --film 成片.mp4 --sheet 6 --out-dir .
# ② 出封面：--source + --plan 会让脚本把成片时间映射回源片时间，取没烧录字幕的干净帧
python3 scripts/cover.py --film 成片.mp4 --at 8:09 --source 原片.mp4 --plan out/resolved.json \
        --out-dir . --prefix "片名S2E02_集名_封面" \
        --above "是，大臣 · 第二季第二集" --title 集名 --below "中文解说 · DOING THE HONOURS" \
        --crop34 right --zoom34 0.92
```
版式固定四行（左下角：金色小字／白色宋体大字／金短线／小字），字号按画宽定比例
（4:3 = 8.33%、3:4 = 11.11%，跨集一致，别每集换大小）；要改版式就改 `cover.py` 顶部的 `LAY`，
**不要每个项目重写一遍排版脚本**。参数卡里不再记封面尺寸——它已经是脚本默认值。

- **成片帧多半带着烧录字幕**（解说白字、对白黄字都在画面下部，正好压在标题上）：给了
  `--source` + `--plan` 脚本就取源片那一帧的干净版（唯一差别就是没字幕）。
- **3:4 竖裁是宽片的取舍**：默认居中会把两张脸各切一半——用 `--crop34 right` 选主体、
  `--zoom34 0.92` 再放大一点，把切脸的前景挤出画外。

### 第 7 阶段之后（**按需**）：原声切点修版 —— 「字幕在、声音不全」/「声音多留一小截」

**默认不走这一步。** 正常流程第 3 阶段用「SRT 句末 +0.35s」定彩蛋终点就够了；只有用户看片后
反馈下面两种现象时才用：

| 用户说法 | 实际毛病 | 方向 |
| --- | --- | --- |
| 「原声片段最后有字幕，但声音不全 / 只听到半句」 | 段末切在句子中间，末词被啃 | 切早了（A） |
| 「原声片段结尾多冒出一小截声音，没有字幕」 | 段末切在下一句的开头，多留了一截 | 切晚了（B） |

两种是同一个病根：**切点落在台词里**。修法也相同——把段末挪到一句完整话音之后的换气缝里。
```bash
# ① 体检：逐段报告切点是否合格 +（--suggest）给出可选的缝和建议的 pe
python3 scripts/cut_audit.py --plan out/resolved.json --source 原片.mp4 --srt 原片.srt --suggest
# ② 挑一个缝 → pe = 缝中心 - 0.35，改 plan.json 里该段 punch 的第二个数（注意 b < 下一段起点）
# ③ 重跑，并加 --snap-cut 0.3（默认 1.55s 会把段末吸到附近镜头切点上，常常又吸回台词里）
python3 scripts/timeline.py --plan plan.json --audio-dir norm --narration-dir narration \
        --source 原片.mp4 --out-dir out --track --dlg-srt 原片.srt --dlg-skip 1,2,3,4 \
        --fixed-tail 2.0 --snap-cut 0.3 <字幕样式参数照抄>
# ④ 6c/6d/6e：fix_subs_punct → calibrate → render → verify
# ⑤ 复听：对新切点前 2.6s 做 ASR，确认末句完整
python3 scripts/probe.py --source 成片.mp4 <切点-2.6> --dur 2.6
# ⑥ 再跑一次 ① 确认全绿；参数卡记一笔（根因/改了哪几段/片长增量）
```
**三条判据**（`cut_audit.py` 自动查，全部满足才算合格）：
1. **不啃句、不多留**：段末落在 ≥0.3s 的「无语音缝」里。阈值自动标定 = 窗口内帧峰值
   85 分位 − 9dB（对白峰值一般 −5~−12dB、环境声 −20~−30dB，缝就在两者之间）；
   也可 `--thr` 手工指定。
2. **不闪字幕**：段末前 0.15s 内不能有 SRT 行起始，否则出现一句「有字幕、没声音」的短闪。
3. **字幕拖尾 ≤0.45s**：末条字幕比该句语音最多多留 0.45s（字幕比语音早退是 SRT 自身的时偏，只提示）。
段末落在笑声/音乐里、附近又没有字幕行时记 ⚠ 不记 ✗——那种不涉对白，但要人工确认一句。
**第 4 条：末段实裁（自动）**。全片最后一段（或 SRT 末行横跨切点）且上面判据不干净时，
`cut_audit.py` 自动在切点附近取 **3 个不同位置的窗外 ASR 采样、末句止取最大**——切点之后
还有话音 → ✗ 啃句（并给出 pe 至少要到多少）；采样全干净时还要 SRT 不反对才推翻 ✗（横跨
切点的字幕行止点超出切点 >0.3s → 保守按啃句：假 ✗ 只需人工复听一句，假 OK 等于把没说完
的结尾直接交付）。多样本是因为 ASR 对「句尾混着音乐」的窗有方差，单发会假阴性。
**这一条的 ✗ 不许用「本季 SRT 偏早」一律驳回**——S3E05 全剧最后一句 "Yes, Minister!"
被啃，就是末段 ✗ 被连带驳回 + 「下一句起点」判据对末段没有下一句、vacuously 通过，
三道校验同时漏掉。`--no-asr` 可关（纯离线）。真实复测：改后用 S3E05 原素材重跑，
末段报「末句止 1721.69 > 切点 1720.71，pe 至少要到 1721.69」。

**为什么不能拿 SRT 当语音边界**：字幕组的行间隔常常只有 ~0.17s，「句末+0.35s」几乎必然落进下一句；
且 SRT 起止比真实语音早/晚 0.2~1.1s（实测同集内两个方向都出现过）。能量法是唯一可靠的地基。
修版是**加原声不加解说**：片长只会变长（一集 +25~30s 量级），解说配音一行都不用动，
`norm/manifest.json` 原样复用；只用重跑 timeline 之后的 6c–6e。

## 常见问题与对策

| 问题 | 症状 | 对策 |
| --- | --- | --- |
| **开头不抓人** | 用户："上来就念背景，划走了" | 铁律 2：t=0 就有人声；第一段解说压在原片片头上；不要片头卡/标题条；`validate.py` 会查"开头没人声/太空" |
| **TTS 服务端截断** | 一段 40 字只出 15 秒，ASR 覆盖率 <0.7 | `narration.py` 自动重试；连续失败就把该段文本按句号拆成两段分别合成 |
| **覆盖率误报（ITN 数字）** | 内容完整却报 0.87 | 已修：`canon()` 把中文数字与阿拉伯数字双向归一（一九七九 == 1979，百分之三点五 == 3.5%，**十万 == 10万**）。写稿时顺手跑 `lint_narration.py`，大数字会列为 INFO 提示 |
| **解说把话安到了错的人头上** | 用户听出「这段不是他说的」：典故、计划、口述被安到另一个人名下 | 写稿时**按源转写逐句核说话人**，别凭印象。第六集有 3 处：典故是汉弗莱不是伯纳（`Remember a member of the government…`）、层层打电话是汉弗莱补的链条不是伯纳的计划、便条是汉弗莱口述伯纳记录。核完把台词时间戳记进参数卡，返工有据 |
| **配音全跑完才发现语速不对** | 探针句与真实解说的停顿不同，标定偏一点 | 已修：pilot 用真实解说分位取样标定（`--pilot 5`）。仍要返工时用 `--recalibrate`，别手改 `.pacing.json` |
| **改完解说词重跑还是旧声音** | `audio/` 里的 mp3 是指纹缓存的 | `narration.py --only <段> --force`；整批换稿才清 `audio/` |
| **同一设置语速漂移** | 同音色同指令，净吐字率实测 4.7–6.1 | `--target-artic` 归一提字率 + 全局唯一 `--speed` + `atempo` 收残差；别逐段换 speed |
| **听感"这段话特别快"但报表全绿** | 整段节奏每段都 = 目标值 | 指标错了：要看**净吐字率**（`silencedetect` 剔除停顿后再算） |
| **吐字率归好了还觉得赶** | 每秒字数一致但某几句连成一口气 | 看**最长连续发声**；`--max-run` 会在段内最深能量谷点插停顿（别按字数硬切）。它是安全网，不是常规手段：只在真长跑上开火才划算 |
| **换音色后响度对不上** | 解说被原声压住或过响 | 必须 `--level-mode speech` 让 `--target-db` 真正生效；`auto` 模式下 `alimiter` 自动电平会顶到 0dBFS |
| **换音色后复用旧音频** | 改了 `--voice` 但声音没变 | 已修：`audio/.meta.json` 指纹（文本+音色+指令+speed），变了就重合成 |
| **半成品/坏段落混进片子** | 剪辑里有段声音不对 | 已修：`norm/manifest.json` 只收录验过的段，timeline 默认拒收未验段（`--allow-unverified` 放行） |
| **剪辑末尾留 1 秒碎镜头** | 原声说完后画面闪一下新场景 | 末端吸附镜头切换点 + 末镜 ≥1.5 秒（自动） |
| **彩蛋被掐半句** | 金句只听到前半 | 彩蛋终点 = 句子结束 + 0.35 秒再吸附切点；起点用能量法吸附到整句开头 |
| **彩蛋没有铺垫** | 观众听不懂这句为什么好笑 | 每条彩蛋的上一句解说必须是它的铺垫 |
| **解说压在原声窗上** | 白字幕盖在放原声的地方 | 已修：解说窗做区间合并 + `validate.py` 查重叠；`verify.py` 还会核对字幕与原声窗零交叠 |
| **黑条底部漏一道原片** | 解说时画面最底下还露着原片/原字幕一条（S1E1 用户第一轮就报） | 承载带写死了高度：`y=1812 h=294` 只铺到 y2106，离底边差 54px。改用 `--sub-band`（`h=ih-N` 封到底），并把不透明区起点提到字幕带顶上方 36px |
| **对白字幕全片错窗** | 半数对白事件压在同段解说上 | `resolved.json` 的 `narr.gs` 是**成片绝对时间**，段内相对要 `g - start` |
| **全剧最后一句被啃（收尾梗/标题梗 cut 半截）** | 用户：「最后一句没说完就结束了」：原声末词被切在半截，黄字幕却显示完整 | 三个漏洞同时打开才会漏：① 分块 ASR 长块吞尾，台词表末句是残句（probe.py 已自动短窗补测）；② 「下一句起点 − pe」判据对全剧最后一句没有下一句、vacuously 通过（改用越过 pe 的窗外 ASR 核）；③ cut_audit 末段 ✗ 被「SRT 偏早」连带驳回（现在末段自动窗外 ASR 实裁，✗ 不可一律驳回） |
| **字幕拆行把标点甩到行首** | 行首出现 `”汉弗莱…`、`，公认的…` | 已修：折行按像素宽度且在标点后断（不再按字数硬断）；`fix_subs_punct.py` 只动白字幕、只同一样式内回移，作为兜底 |
| **原声段落没有中文** | 用户："放原片的时候完全不知道在说什么" | `timeline.py --dlg-srt 原片.srt` 把中文台词贴到原声全音量窗（白解说/黄对白） |
| **原声片段结尾「有字幕、声音不全」/「多冒出一小截」 | 用户看片发现的啃句/多留：段末切在台词里（SRT 行间隔常只有 ~0.17s，"句末+0.35s"必落进下一句） | 按需修版：`scripts/cut_audit.py --plan out/resolved.json --suggest` 按「−20dB/0.3s 语音缝」重定段末 + `--snap-cut 0.3`，再走 6c–6e；**默认不用**，只在用户反馈后跑 |
| **片名/来源没交代** | 观众不知道这是什么剧 | 放在**解说第一句**里（钩子的一部分），不要靠标题条 |
| **字幕组水印没挡住** | 片头底部有"压制/字幕"字样 | 抽帧量出水印 y 带，用底部信息条（`--info-bar`）按时段盖住；顶部水印用 `--top-bar` 或干脆不处理 |
| **成品文件被渲染进程覆盖** | 用户播放失败（缺 moov 索引） | 一律渲染到 `<out>.part.mp4` → 校验 → 原子替换 + 备份（`render.py` 内置） |
| **抽帧预览的字幕全是开头那条** | `-ss` 放在 `-i` 前 + `subtitles=` 滤镜 | 滤镜时间戳被归零。两步法：先用 `-loop 1` 喂底图、滤镜后再 `-ss`（`style_preview.py` 就是这么做、`\fad` 淡入的那一帧才不会抽成空白） |
| **黄对白字幕比解说小一圈** | 原片 SRT 正文带 `{\fs18}`，libass 真按 18px 画，样式定 58px 也没用 | 已修：`read_dlg_srt`/`dlg_text` 剥掉 `{\...}` 与 `<font>` 标记（实测黄字包围盒 136×11px → 439×38px） |
| **verify 报「原声窗覆盖 0%」但其实没对白** | 片头纯音乐段 + 字幕组信息行含中文被当成对白 | 已修：`read_dlg_srt` 丢弃字幕组/水印行（关键词都带冒号或专有名词，"压制消息"不误伤），`verify.py` 也有 `--dlg-skip` |
| **verify 说响度差 2.4dB，全片普查却是 0** | 只抽"时长最长的 4 段"，原片逐场电平能差 7dB，抽 4 窗噪声 ±2.5dB | 已修：`census_windows` 全片普查（每个片段一窗、两类同批段），结果里报样本数与离散度；`calibrate.py --samples 0` 为默认 |
| **片尾演员卡文字撞解说字幕** | 白字压在 "as James Hacker" 上 | 片尾段用 `--narlow-last N` 切低位样式（MarginV≈2.4% 画面高） |
| **封面底图上压着字幕** | 用户挑的那一帧正好在放对白/解说 | `cover.py` 给 `--source` + `--plan`：把成片时间映射回源片时间取干净帧；也能先用 `--sheet N` 让用户挑一个没有字幕的位置 |
| **3:4 封面把两张脸各切一半** | 宽片竖裁，居中取景 | `cover.py --crop34 left\|right` 选主体，`--zoom34 0.9~0.95` 再放大把切脸的前景挤出画外 |

## 常见异常与自检（脚本会自己报）

| 现象 | 含义 | 怎么办 |
| --- | --- | --- |
| `★重排失败 净吐字率 X ≠ 目标` | 该段音频被服务端改过语速/截断 | 重跑该段（`--only X --force`）；仍失败就把这句按句号拆开 |
| `✗ 共 N 项解说音频不可信` | manifest 里没有/未验证/sha1 不符 | 先 `narration.py --only …` 补齐；确认要带病出片才加 `--allow-unverified` |
| `⚠ 解说遮蔽窗有 N 处重叠` | 该片段装不下这些解说 | 加长片段或删句（`validate.py` 会指出是哪一段） |
| **钩子念完片头卡拖太长** | 用户："解说说完了片头还在放" | fixed 段解说完后原片只再留 2s（`--fixed-tail 2.0` 默认；想留剧名卡就把 fixed 终点写到卡后） |
| `⚠ 开头 X 秒才出第一句解说` | 违反铁律 2 | 把 `items[0]` 改成 `{"fixed":[0,片头长度],"units":["钩子段"]}` |
| `⚠ 块 X 尾部空缺 Ns（长块 ASR 吞尾）→ 短窗补测` | 分块 ASR 把块尾的一小段吞了（S3E05：全剧最后一句被吞半截） | 补测结果自动合回台词表；看完「现末句止」再定末个彩蛋的 pe，并用越过 pe 的窗外 ASR 复核 |
| `⚠ 原声提升被限到 +N dB` | 原声峰值要撞限幅器 | 提高解说电平上限不行，改把解说压低或加大 `--duck` |

## Pitfalls

- StepAudio 的 ASR 时间戳不可信（返回全 0）；qwen filetrans 的句级/词级是真值（词级是分词块、不是逐字 cue），`probe.py --transcribe` 已直接采用。短窗探测（`probe.py` ②③）留给抽查与没时间戳的模型。
- **别把同一个滤镜输出 label 直接接给 sidechaincompress 和 amix**：ffmpeg 7.x 实测会静默丢掉解说一路；
  `render.py` 用显式 `asplit` 分流。任何音频链改动后，先用"纯解说段 vs 纯原声段各取 8s 复刻对比 RMS"验证。
- **承载带必须封到画面底边，且不透明区必须盖住原片字幕带顶**。写死高度（`y=1812 h=294`）会在底边漏出
  原片一道（2886×2160 上漏 54px，S1E1 用户第一轮就报）；用 `h=ih-N` 让渲染器自己算到底。反过来，
  上沿渐变只允许出现在字幕带**上方**——渐变压到字幕行上，原字幕会从半透明区透出来成鬼影
  （S1E1 v3 的 0.93 半透明条就是这么被否的：盖烧录字幕只能 1.0 全黑）。
- 别用 instruction 里的"语速偏慢"控速，它不生效；语速只能靠 `--speed` + `atempo` 实测校准。
- `atempo` 的合理区间 0.9–1.12；超出就换 `--speed` 重合成，硬拉会听出金属味。
- **`ffmpeg` 的 `volumedetect` mean_volume 其实是 RMS**（0.5 幅度正弦实测 −27.10 dB）；写电平脚本时别用
  mean(|x|) 去对，会差 4 dB 以上。
- **`alimiter` 默认 `level=1` 开自动电平**，会把每段峰值顶到 0dBFS，`--target-db` 失效；
  要让它生效必须 `level=disabled`（也就是 `--level-mode speech`）。
- StepFun **国际版端点不返回词级时间戳**：`--subtitles` 被静默忽略；`--no-itn` 也不阻止中文数字被归一成
  阿拉伯数字（所以比较前必须自己归一，见 `canon()`）。
- **渲染默认 GPU 编码（`--encoder vaapi` = 软解 + CPU 滤镜 + `h264_vaapi`），别退回纯 CPU**。
  本机（RX 9070 / Ryzen 5 3600）60s 基准：x264 medium crf20 = 23.8s wall / 258 CPU-s；
  vaapi qp20 = 5.8s / 24 CPU-s（**wall 快 4.1 倍、CPU 少 10.7 倍**），且 PSNR 47.83 vs 47.34dB、
  文件还小 8%——本素材上 GPU 编码没有画质代价。`subtitles`/`drawtext` 只有 CPU 实现（实测 <1% CPU，
  但单线程、是串行点，省不掉）。两个反直觉点：
  ① **别一并联硬解**（`-hwaccel vaapi`）：烧字幕必须 hwdownload→CPU→hwupload 两次全帧拷贝，
  wall 反而从 5.8s 涨到 9.6s；② **别手动写 `-bf 0`**：同 qp20 文件从 26.8MB 涨到 36.6MB。
- **别用 A/B 试听当验证手段**：两版的净吐字率被 atempo 强制成同一个值，比的是恒等式；
  要看 narration.py 报表里的量化指标 + ASR 回读覆盖率。
- **TTS 有约 ±8% 的"会话级"语速漂移**：`--speed` 负责音色质感一致，`atempo` 负责速率精确，两者不能互相替代。
- **分块 ASR 会在长块尾部吞句**：台词表最后一行不等于全剧最后一句（S3E05 的 "Yes, Minister!"
  被吞成 "Yes."）。`probe.py --transcribe` 现在自动补测并报「现末句止」；看到 ⚠ 尾部补测，
  末个彩蛋的 pe 必须按补测结果改，并用越过 pe 的窗外 ASR 复核。
- 探静音用 `-42dB / 0.15s`：0.15s 以下的气口不当停顿。
- 服务端 TTS 并发上限约 8、ASR 也有限流；`-j` 建议 3–4。
- 源片烧录字幕占底部，解说字幕要往上让；**不要为了美观裁掉原片字幕**（那会同时裁掉画面）。
- **判断后台任务是否结束不要用 `pgrep -f`**：会自匹配，白等。用 `scripts/bgrun.sh` + `bgwait.sh`，
  或前台加足够大的 timeout 直接跑完。
- **`--gap` 默认值来自 `profile.json`**，不要在命令里硬写 0.30/0.45：两边不一致时
narration 的遮蔽窗与 timeline 的解说窗会差 0.15 秒，表现为"解说压在原声上"或假的重叠告警。
- **别用 `sleep` 猜任务多久完成**：短任务前台跑，长任务 bgrun+bgwait（超时有 124 兜底）。

## Verification

```bash
python3 scripts/verify.py --film 成片.mp4 --plan out/resolved.json --ass out/narration.ass \
        --source 原片.mp4 --dlg-srt 原片.srt --out-dir out      # 9 项自动核对，全绿才算完
sh tests/run.sh                                              # 流水线本身还健康吗（离线冒烟，含封面步）
```
交付前人工只核两处：① 每条彩蛋窗首尾整句（第 2 阶段逐窗 ASR 复核的记录）；
② 封面两版目检（标题不压脸、不压烧录字幕，字号与既有封面同档）。
其余（时长/可解码/末镜/电平/字幕/覆盖/PlayRes/峰值/抽帧）都已并入 verify 的 9 项。

更详细的案例数据、指标推导与踩坑记录见 [`references/pipeline-notes.md`](references/pipeline-notes.md)；
`/home/shike/文档/视频剪辑/参数卡.md` 的 S1E4 一节是本集实测栏的写法样板。
