# 子代理任务模板（机械阶段用）

配音、剪辑、质检这三段是固定命令 + 明确验收标准，不需要剧情上下文。父代理写好这个 brief，
用 subagent 工具派下去，然后去干别的；子代理完成时父会话会被唤醒，**不要轮询**。

## 模板

```markdown
# 任务：<第 5 阶段配音 / 第 6 阶段剪辑 / 第 7 阶段质检>（<片名> S_E_）

## 工作目录
/home/shike/文档/视频剪辑/<剧名>/<第几集>/work

## 输入（都在上面的目录里）
- 解说词：narration/（每段一个 .txt，共 N 段）
- 计划：plan.json
- 原片：../原片.mp4（或 work/ 下的路径）
- 原片字幕：dlg_zh.txt（有外挂 SRT 时给 SRT 路径）

## 要跑的命令（照抄，不要改参数）
cd <工作目录>
python3 <skill>/scripts/narration.py --dir narration --audio-dir audio --out norm -j 4

## 验收标准（逐条回报实际数字）
- narration：结尾三行汇总给出净吐字率极差/CV、连续发声上限、总时长；每段 cov ≥ 0.90、
  atempo 0.9–1.12；`norm/manifest.json` 里 N 段全部 verified
- timeline：`out/resolved.json` 生成、无必须修问题；`out/narration.wav`、`out/narration.ass` 存在
- calibrate：把建议的两个增益（`--volume-orig` / `--volume-narr`）原样回报；若出现「原声提升被限到 +NdB」
  或「解说要动超过 2dB」这类告警，**先别渲染**，连告警原文一起回报，等父代理定了增益再跑 6e
- verify：`N/9 通过`，把失败项的原文贴回来

## 只准回报这些
1. 每条命令的退出码
2. 验收标准里的实际数字
3. 产物路径（绝对路径）
4. 失败时：报错原文最后 20 行

## 约束
- 不许改 narration/ 里的任何 .txt、不许改 plan.json、不许改 skill 里的脚本
- 增益数字不自己拍：calibrate 给什么就回报什么，告警时停下（听感判断归父代理）
- 参数要调、稿要改：停下来回报，由父代理决定
- 时间预算：预计 X 分钟；超了就把已跑完的部分回报，别硬等
```

## 父代理这边

1. brief 里的路径、段数、参数都由父代理填好——子代理不该去猜。
2. 子代理回来先看**验收标准的数字**，不是看"跑完了"三个字。
3. 指标红了：父代理判断是稿子问题（改稿，回到第 3 阶段）、参数问题（改 profile.json 后重跑），
   还是工具误报（修 skill）。**这三种判断都不要外包。**
4. 子代理回报"改不了、要你决定"的时候，通常就是需要判断的那一步——接着干，别把它再派下去。
